# 相关工作地图

核心判断：这个项目不是从零出现；它站在 VLA、LLM 机器人规划、代码生成、harness engineering、代码自进化和安全验证的交点上。潜在新意来自把这些部分组织成一个面向真实机器人失败修复的闭环。

## 路线总览

| 路线 | 代表工作 | 已解决什么 | 留给本项目的空白 |
| --- | --- | --- | --- |
| VLA / robot foundation model | RT-2、OpenVLA、pi0、GR00T、Gemini Robotics | 从视觉和语言直接生成动作，学习跨任务泛化。 | 失败难解释，修复常依赖数据和训练；skill 版本与回归测试不显式。 |
| VLA + agentic harness | Harness VLA | 把冻结 VLA 作为 contact primitive，用 planner、memory、解析控制和重试处理部署扰动。 | 固定 primitive，不修改 skill 代码；主要是仿真证据，尚无真实机器人安全演化。 |
| LLM + 预定义 skill | SayCan、Inner Monologue | LLM 做高层计划，skill/value function 提供 grounding。 | 通常不自动改写 skill 实现。 |
| LLM 生成机器人代码 | Code as Policies、VoxPoser、ProgPrompt | LLM 能把语言任务转成程序、几何计算和 API 调用。 | 多数偏一次性生成，长期维护、回归、安全部署不足。 |
| lifelong skill library | Voyager、LRLL | skill 能以代码或抽象库形式不断增长。 | Voyager 在游戏环境；LRLL 更偏新 skill 抽象，不完全是失败驱动的程序修复。 |
| 代码自进化 + evaluator | Eureka、AlphaEvolve、自调试代码研究 | 证明 LLM 改代码需要可执行评估器，且能迭代优化。 | 机器人 evaluator 更难，因为失败多模态、物理、时序、带安全风险。 |
| Harness 自进化 | STOP、Self-Harness、AHE、DGM | 把 context、workflow、tool、memory 和 harness code 变成可评估的编辑对象。 | 主要证据来自 coding/QA/science；必须把 verifier、trace 和安全权限放在循环外。 |
| 安全与形式化验证 | NRTrans、SELP、SafePlan、LTLCodeGen、SAFER | 约束 LLM 生成的计划/程序，降低危险行为。 | 需要和 skill repair、CI/CD、版本管理整合。 |
| Benchmark / 仿真 | LIBERO、CALVIN、RoboCasa、BEHAVIOR-1K、RoboLab | 提供可复现实验环境和任务集。 | 需要构造“故意有缺陷的 skill + 自动修复”的 benchmark。 |

## 第一批精读论文

- [[Wiki/02-相关工作/论文精读/Code as Policies]]、[[VoxPoser]]、[[SayCan]]：说明 LLM 如何写机器人代码、生成几何中间表示、以及在可执行 skill 上做 grounding。
- [[Voyager]]、[[AlphaEvolve]]：说明代码技能库和 evaluator 驱动的自进化为什么可行。
- [[RT-2]]、[[OpenVLA]]：代表端到端 VLA baseline，也是本项目必须正面对照的主线。
- [[NRTrans]]：说明机器人代码生成必须受 DSL、compiler 和 debugger 约束。
- [[LIBERO]]、[[RoboCasa]]：提供 lifelong/regression 和厨房任务仿真的实验入口。
- [[Harness VLA]]：给出当前最直接的“冻结 VLA + 固定 primitive + memory-guided planner”混合 baseline。
- [[Harness Engineering for Self-Improvement - 综述解读|Harness Engineering for Self-Improvement]]：把 skill repair 放进更大的 harness evolution 图景，并明确可观测性与只读 verifier 边界。

## 新增的直接近邻

[[Harness VLA]] 让“VLA 是 skill 的一种实现”从架构推断变成了 benchmark 证据，也收紧了本项目的创新要求：仅做 planner re-grounding、reference trace memory、解析 primitive 和 VLA retry 已不足以形成新的主张。

[[Harness Engineering for Self-Improvement - 综述解读|Harness Engineering for Self-Improvement]] 不是单篇实证论文，而是 2026 年 harness 研究的二级综述。它最有价值的作用是提供术语和实验纪律：区分 harness-updating 与 harness-benefit，并让 tracer、verifier、held-out tests、预算和权限成为不可编辑可信内核。

## 核心阅读优先级

如果只按“对代码自进化 robot skill library 这个项目的直接相关性”排序，最重要的不是平均机器人性能最强的 VLA 论文，而是能支撑 skill 生成、失败修复、evaluator 和安全门的工作：

1. [[Wiki/02-相关工作/论文精读/Code as Policies]]：最直接证明 LLM 可以把感知 API、几何计算和控制 primitive 编成 robot policy code；它适合作为本项目 one-shot code generation baseline。
2. [[Voyager]]：最像本项目的思想近邻，展示 executable skill library、环境反馈、执行错误和自验证如何形成 lifelong code-skill 积累。
3. [[AlphaEvolve]]：说明代码自进化的核心是 evaluator，而不是让 LLM 自由改代码；它是设计 robot skill evaluator 和版本数据库的上位参考。
4. [[NRTrans]]：给出 Robot Skill Language、compiler 和 debugger 的安全路线，直接支持“coding agent 只能提交受约束 patch proposal”的系统边界。
5. [[SayCan]]：定义“LLM planner + skill affordance/value grounding”的任务大脑范式，说明高层计划必须被当前 embodiment 和 skill 可执行性约束。
6. [[VoxPoser]]：证明 LLM/VLM 可以生成 3D value map 和约束，再交给 model-based planner，适合作为“代码 + 几何中间表示 + 传统控制”的机器人实现参考。
7. [[LIBERO]]：最适合把“修复一个 skill 是否破坏旧任务”变成 lifelong/regression 指标。
8. [[OpenVLA]] 与 [[RT-2]]：不是本项目机制的核心来源，但必须作为 VLA 主线 baseline；它们帮助界定本项目不是替代 VLA，而是补充可解释、可测试、可回滚的 skill 演化层。

## 本项目的可发表切口

如果想变成论文，最清晰的问题不是“机器人能不能 AGI”，而是：

> 给定失败的机器人 skill、执行 trace 和测试环境，LLM coding agent 能否提出安全 patch，使相似场景成功率提高，同时不破坏旧任务？

这个问题有明确输入、输出、指标和 baseline。

## 可能的论文定位

标题可以类似：

> Self-Debugging Robot Skills: Execution-Feedback Program Repair for Embodied Manipulation

贡献可以是：

1. 一个 skill registry / DSL。
2. 一个多模态 execution trace schema。
3. 一个 failure attribution + code repair agent。
4. 一个 simulation-to-hardware verification pipeline。
5. 一个包含故意缺陷 skill 的 benchmark。
6. 真实机械臂或高质量仿真实验。

## 关键判断

这个项目应避免和 VLA 正面争“谁通向 AGI”。更好的位置是：

> VLA 负责从数据中学习难以手写的连续控制；code-evolving skill layer 负责让可解释技能、约束、fallback 和测试在真实部署中持续变好。

也就是说，VLA 可以是 skill 的一种实现方式，而不是一定要被替代的敌人。
