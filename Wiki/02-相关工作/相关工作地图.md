# 相关工作地图

核心判断：这个项目不是从零出现，而且 ASPIRE/VASO 已覆盖宽泛的 robot program/skill evolution 闭环；当前潜在新意必须收紧到 frozen VLA harness 中跨任务共享 implementation 的受限修复、干预路由与 hidden regression/safety 验收。

## 路线总览

| 路线 | 代表工作 | 已解决什么 | 留给本项目的空白 |
| --- | --- | --- | --- |
| VLA / robot foundation model | RT-2、OpenVLA、pi0、GR00T、Gemini Robotics | 从视觉和语言直接生成动作，学习跨任务泛化。 | 失败难解释，修复常依赖数据和训练；skill 版本与回归测试不显式。 |
| VLA + agentic harness | Harness VLA | 把冻结 VLA 作为 contact primitive，用 planner、memory、解析控制和重试处理部署扰动。 | 固定 primitive，不修改 skill 代码；主要是仿真证据，尚无真实机器人安全演化。 |
| LLM + 预定义 skill | SayCan、Inner Monologue | LLM 做高层计划，skill/value function 提供 grounding。 | 通常不自动改写 skill 实现。 |
| LLM 生成机器人代码 | Code as Policies、VoxPoser、ProgPrompt | LLM 能把语言任务转成程序、几何计算和 API 调用。 | 多数偏一次性生成，长期维护、回归、安全部署不足。 |
| Agentic robot program repair | ASPIRE | 用 per-primitive multimodal traces 诊断、修复和验证 code-as-policy 程序，并把有效修复沉淀为可检索 skill guidance。 | 需要进一步检验：跨任务共享的既有 skill implementation 能否在 VLA harness 内被最小化修复，并通过 hidden regression/safety gate。 |
| lifelong skill library | Voyager、LRLL | skill 能以代码或抽象库形式不断增长。 | Voyager 在游戏环境；LRLL 更偏新 skill 抽象，不完全是失败驱动的程序修复。 |
| 代码自进化 + evaluator | Eureka、AlphaEvolve、自调试代码研究 | 证明 LLM 改代码需要可执行评估器，且能迭代优化。 | 机器人 evaluator 更难，因为失败多模态、物理、时序、带安全风险。 |
| Harness 自进化 | STOP、Self-Harness、AHE、DGM | 把 context、workflow、tool、memory 和 harness code 变成可评估的编辑对象。 | 主要证据来自 coding/QA/science；必须把 verifier、trace 和安全权限放在循环外。 |
| 安全与形式化验证 | NRTrans、VASO、SELP、SafePlan、LTLCodeGen、SAFER | 约束 LLM 生成的计划/程序；VASO 进一步用 model-checker counterexample 更新可复用 semantic skill contract。 | 形式 contract 的保证依赖 proposition mapping；还需和具体 implementation repair、经验回归、版本管理整合。 |
| Benchmark / 仿真 | LIBERO、CALVIN、RoboCasa、BEHAVIOR-1K、RoboLab | 提供可复现实验环境和任务集。 | 需要构造“故意有缺陷的 skill + 自动修复”的 benchmark。 |

## 已入库的基础锚点

- [[Wiki/02-相关工作/论文精读/Code as Policies]]、[[VoxPoser]]、[[SayCan]]：说明 LLM 如何写机器人代码、生成几何中间表示、以及在可执行 skill 上做 grounding。
- [[Voyager]]、[[AlphaEvolve]]：说明代码技能库和 evaluator 驱动的自进化为什么可行。
- [[RT-2]]、[[OpenVLA]]：代表端到端 VLA baseline，也是本项目必须正面对照的主线。
- [[NRTrans]]：说明机器人代码生成必须受 DSL、compiler 和 debugger 约束。
- [[LIBERO]]、[[RoboCasa]]：提供 lifelong/regression 和厨房任务仿真的实验入口。
- [[Harness VLA]]：给出当前最直接的“冻结 VLA + 固定 primitive + memory-guided planner”混合 baseline。
- [[Harness Engineering for Self-Improvement - 综述解读|Harness Engineering for Self-Improvement]]：把 skill repair 放进更大的 harness evolution 图景，并明确可观测性与只读 verifier 边界。

## 新增的直接近邻与 Novelty 压力

[[Harness VLA]] 让“VLA 是 skill 的一种实现”从架构推断变成了 benchmark 证据，也收紧了本项目的创新要求：仅做 planner re-grounding、reference trace memory、解析 primitive 和 VLA retry 已不足以形成新的主张。

[[Harness Engineering for Self-Improvement - 综述解读|Harness Engineering for Self-Improvement]] 不是单篇实证论文，而是 2026 年 harness 研究的二级综述。它最有价值的作用是提供术语和实验纪律：区分 harness-updating 与 harness-benefit，并让 tracer、verifier、held-out tests、预算和权限成为不可编辑可信内核。

[[ASPIRE]] 是当前最强 novelty threat：它已经把细粒度多模态 trace、agentic failure diagnosis、program repair、closed-loop validation、skill library 和 evolutionary search 串成机器人持续学习系统。它主要在 CaP-X 中生成和修复 task program，并把经验存成 in-context guidance；因此本项目若继续，必须把对象收紧到“冻结 VLA harness 中跨任务共享的现有 skill implementation”，并证明相对 plan/memory-only baseline 的增量、跨任务回归和安全验收。

[[VASO]] 则表明“verification-guided self-evolving skill”这个表述也已经被占据。VASO 更新的是带 LTL 规格和 proposition mapping 的 semantic skill contract，而不是 manipulation skill 的具体 Python implementation；本项目应明确自己研究的是经验执行证据驱动的 implementation repair，并把 formal contract 作为 verifier 的一种可组合安全门。

这一区分及实验操作化定义见 [[问题定义与实验假设]]。

## 核心阅读优先级

如果现在只读七篇，顺序应服务于“项目是否仍有独立问题”和“实验能否证伪”，而不是再扩展通用机器人论文面：

1. [[ASPIRE]]：先做 novelty audit；重点对照 repair 对象、skill library 表示、debug/eval split 和跨任务迁移。
2. [[VASO]]：界定 verifier-guided skill evolution 已做到哪里，以及 empirical Robot CI 与 formal model checking 的差别。
3. [[HELM]]：先建立 memory + verifier + rollback/replanning 的强非代码恢复对照，并借鉴 LIBERO-Recovery。
4. [[DebugRepair]]：再把“结构化中间运行态是否改善 root-cause repair”变成 H5 trace ablation。
5. [[SAFE]]：学习跨任务 failure monitor 和 conformal threshold，避免把触发 repair 当作免费 oracle。
6. [[STING]]：检查 hidden regression suite 是否足以拒绝 plausible-but-wrong patch。
7. [[vla-eval]]：冻结并隔离跨 benchmark evaluator，降低协议差异和复现偏差。

之后再补 [[InSight]]、[[RepairAgent]] 和 [[RoboCritics]]，分别理解 policy/data acquisition、agentic program repair workflow 和 motion-level safety critic。Code as Policies、Voyager、AlphaEvolve、NRTrans、Harness VLA 仍是基础锚点，但当前不应排在新近直接近邻之前。

## 本项目的可发表切口

如果想变成论文，最清晰的问题不是“机器人能不能 AGI”，而是：

> 在固定 RPent/Harness VLA 的 planner、VLA、初始 memory、evaluator 和双预算后，允许 coding agent 只修改受限的共享 skill implementation，能否在预注册的 code-repairable failures 上超过 compute-matched plan/memory-only baseline，并通过 final-blind、跨任务 regression 与 safety gate？

这个问题不仅有明确输入、输出和指标，还把“代码编辑”变成唯一核心处理变量。操作化定义见 [[问题定义与实验假设]]。

## 可能的论文定位

当前建议标题：

> Beyond Fixed Harnesses: Verifier-Guided Program Repair for Embodied Robot Skills

贡献假设应集中在：

1. 按最小充分干预预注册 plan/memory、code、policy 与 trusted-kernel failure，而不是让 repair agent 事后定义适用范围。
2. 在同一 frozen hybrid VLA harness 上用 `Δmemory × Δcode` 设计隔离共享 implementation repair 的增量效应。
3. 用 deliberate + natural defects、final-blind transfer 和 mutation-strengthened regression 检验 patch 是否语义正确、跨任务且无回归。
4. 用只读 Robot CI、安全门和回滚控制共享代码资产的部署。

skill registry、trace schema 和 coding agent 是必要基础设施，但在 ASPIRE 之后不能单独列作主要 novelty。

## 关键判断

这个项目应避免和 VLA 正面争“谁通向 AGI”。更好的位置是：

> VLA 负责从数据中学习难以手写的连续控制；code-evolving skill layer 负责让可解释技能、约束、fallback 和测试在真实部署中持续变好。

也就是说，VLA 可以是 skill 的一种实现方式，而不是一定要被替代的敌人。
