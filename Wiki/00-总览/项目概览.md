# 项目概览

核心判断：这个项目最有价值的表述不是“用 coding agent 直接替代 VLA”，而是“让机器人 skill 像软件一样，在执行反馈、测试和安全门的约束下持续自调试和自进化”。

用户原始想法可以压缩成一个系统：

> 任务大脑负责理解指令和调度 skill；传统/学习混合控制系统负责安全执行；coding agent 负责根据失败 trace 修复 skill 代码；验证系统决定 patch 能不能进入 skill library。

从 [[机器人Harness工程]] 的角度看，这是一套包围 planner、VLA 和传统控制的机器人运行时：它规定模型能看到什么、能调用哪些 skill、如何保存 memory 和 trace、怎样评估修改，以及哪些安全权限必须保持只读。

这和端到端 VLA 的差异在于，VLA 通常追求：

> 图像 + 语言指令 -> 动作

而本项目追求：

> 图像 + 语言指令 -> 任务计划 -> 调用 skill -> 执行监控 -> 失败归因 -> 修改 skill -> 测试验证 -> 版本化部署

## 第一性原理

机器人要在真实世界工作，至少要解决三件事：

1. 知道“要做什么”：理解人类指令、环境状态和任务目标。
2. 知道“怎么做”：把任务拆成可执行 skill，并让低层控制稳定执行。
3. 知道“失败后怎么变好”：从失败中定位原因，并让下一次更可靠。

VLA 主要把第二点和第三点压进模型参数里。本项目则把第三点外显为一个工程闭环：失败不是只变成训练数据，也可以变成代码 patch、测试用例、约束条件、fallback 策略和版本记录。

## 最小系统图

```text
用户任务 + 观测
      |
      v
任务大脑 / Planner
      |
      v
Skill Registry -----> Skill Executor -----> Execution Monitor
      ^                     |                      |
      |                     v                      v
Verifier / CI Gate <--- Coding Agent <--- Failure Trace
      |
      v
更新后的 Skill Library
```

## 研究定位

这个方向和已有工作有明显连接：

- [[VLA路线]] 说明主流路线正在把视觉、语言、动作端到端整合。
- [[LLM规划与代码生成]] 说明 LLM 已经能做高层规划、调用 skill、生成机器人 policy code。
- [[自进化代码Agent与评估器]] 说明“代码 + 反馈 + evaluator”的循环在游戏、RL 和算法发现里已经有效。
- [[安全验证与机器人DSL]] 说明真实机器人不能让 LLM 自由改 Python，必须有 DSL、编译器、约束和部署门。
- [[Harness VLA]] 直接证明冻结 VLA 可以成为可重试的 contact primitive，由 planner、memory 和解析控制扩展到扰动任务。
- [[机器人Harness工程]] 进一步定义可编辑工作区、component-level observability 和只读 verifier/safety kernel。

因此，本项目的独特切口不是单个组件，而是闭环：

> 真实或仿真机器人执行失败 -> 多模态 trace -> failure attribution -> coding agent patch -> 仿真/回归/安全验证 -> skill library 进化。

## 一句话版本

这是一个“机器人 DevOps”方向：把机器人能力从一次性模型训练，部分转化为可解释、可测试、可回滚的软件技能库演化。
