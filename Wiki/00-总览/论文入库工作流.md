# 论文入库工作流

核心判断：这个 wiki 里的论文不是“读后感仓库”，而是要被编译进项目判断。每篇论文入库时都要回答同一个问题：它如何改变我们对“代码自进化机器人技能库”的设计、实验或边界判断？

## 目标风格

用户偏好的讲解风格接近 PhD advisor：先抓主线，再逐节拆技术细节，用具体例子解释机制，最后指出这篇文章值得怀疑什么、能如何扩展。

所以每篇论文页都应包含：

1. 一句话核心贡献。
2. 它为什么对本项目重要。
3. Section-by-section 技术讲解。
4. 一个具体例子，把抽象机制落到机器人场景。
5. 关键实验和证据。
6. 局限、批判和可扩展方向。
7. 对本项目架构、实验或论文叙事的启发。

## 标准步骤

### 1. 放入 Source

把论文 PDF 放到 `Source/Papers/`。文件名采用：

```text
short-title-arxiv-id.pdf
```

例如：

```text
code-as-policies-2209.07753.pdf
```

### 2. 抽取基本信息

记录：

- 标题、作者、年份。
- 本地 PDF 路径。
- arXiv 或项目链接。
- 页数。
- 摘要里的问题、方法和结果。
- 章节结构。

### 3. 建立论文精读页

论文页放在 `Wiki/02-相关工作/论文精读/`。不要只翻译摘要，要写成面向本项目的研究笔记。

推荐模板：

```markdown
# 论文名

核心判断：...

## 元信息

- 本地 PDF：...
- 链接：...
- 角色：...

## 一句话版

...

## 为什么重要

...

## Section-by-section

### Abstract
...

### Introduction
...

### Method
...

### Experiments
...

### Limitations
...

## 对本项目的启发

...

## 我会追问的问题

...
```

### 4. 写回主题页

如果论文改变了某个主题页的判断，要更新对应页面：

- VLA 论文更新 [[VLA路线]]。
- LLM 规划/代码生成论文更新 [[LLM规划与代码生成]]。
- 代码自进化论文更新 [[自进化代码Agent与评估器]]。
- DSL/验证论文更新 [[安全验证与机器人DSL]]。
- benchmark 论文更新 [[Benchmark与实验平台]]。

### 5. 更新导航和日志

每次入库后：

- 更新 `index.md`。
- 更新 `Source/Literature/资料与论文清单.md`。
- 在 `log.md` 追加一条记录。

## 入库时的判断标准

一篇论文只有在回答以下至少一个问题时，才值得进入核心 wiki：

- 它是否提供了可直接复用的系统模块？
- 它是否是本项目必须正面对比的 baseline？
- 它是否支持或推翻了一个核心假设？
- 它是否提供了实验平台、指标或 benchmark？
- 它是否揭示了真实机器人部署中的关键风险？
