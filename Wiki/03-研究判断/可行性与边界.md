# 可行性与边界

核心判断：这个项目可行，但应定位为“可解释 robot skill 的自调试与自进化框架”，不要定位成“替代 VLA 的通用 AGI 机器人”。

## 为什么可行

第一，机器人系统本来就是模块化软件。感知、坐标变换、规划、控制、状态机、success detector、fallback 和安全约束，都有很多可由代码表达的部分。

第二，很多机器人失败并不需要重新训练大模型。例如：

- 坐标系转换错。
- 深度图无效值没过滤。
- planner error code 没处理。
- 抓取点候选策略太脆。
- precondition 太宽。
- postcondition 太弱。
- fallback 缺失。

这些问题很适合 coding agent 修复。

第三，已有工作已经证明了关键组件：

- LLM 可以高层调度 skill：SayCan、Inner Monologue。
- LLM 可以生成机器人代码：Code as Policies、VoxPoser。
- skill library 可以通过经验增长：Voyager、LRLL。
- 代码可以靠 evaluator 迭代进化：Eureka、AlphaEvolve。
- 机器人 LLM 计划/程序需要验证：NRTrans、SELP、SafePlan。

所以本项目不是空中楼阁，而是把这些趋势组织成一个更工程化的闭环。

## 最有价值的部分

最有价值的不是“LLM 写出一个很聪明的 skill”，而是：

1. 失败 trace 结构化。
2. failure attribution 分类清楚。
3. patch proposal 可审查。
4. evaluator 能判定 patch 是否真的变好。
5. regression suite 防止修复 A 破坏 B。
6. skill library 随时间复利。

这也是它区别于普通 VLA demo 的地方。

## 不能过度承诺的部分

不要承诺：

- 纯靠 coding agent 解决所有低层控制。
- 不需要机器人数据。
- 不需要 learned policy。
- 可以自动安全地在真实机器人上无限试错。
- 短期替代 VLA。

真实情况是：很多操作能力依然需要 imitation learning、RL、diffusion policy、VLA 或专门控制器。coding agent 更适合作为 skill 周围的工程维护者、调试员和系统集成者。

## 最适合 coding agent 修的失败

适合：

- 几何计算错误。
- API 调用和参数错误。
- 阈值和置信度处理。
- fallback 策略。
- precondition/postcondition。
- success detector。
- 异常处理。
- 测试缺失。

不适合：

- 需要高频触觉闭环的灵巧操作。
- 布料、液体、柔性物体的复杂动力学。
- 视觉模型完全没有识别能力。
- 硬件本身不够稳定。
- 没有可测 evaluator 的开放式目标。

## 叙事建议

弱叙事：

> 我们用 coding agent 替代 VLA，实现机器人 AGI。

强叙事：

> 当前 VLA 强大但黑箱、数据饥渴、失败难调试。我们提出 execution-feedback program repair for robot skills，让机器人通过失败 trace 自动修复可解释 skill code，并用仿真、形式约束、回归测试和安全门保证部署可靠性。

后者更科学，也更容易做实验。

## 关键研究假设

可以把项目核心假设写成三条：

1. 对一类可归因机器人失败，代码级修复比模型微调更样本高效。
2. 多模态 execution trace 能显著提高 coding agent 的修复准确率。
3. 带 regression 和 safety gate 的 skill library 能在 lifelong setting 中积累能力，同时控制旧任务退化。

这三条都可以实验验证。
