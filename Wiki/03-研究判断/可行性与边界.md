# 可行性与边界

核心判断：长期的 robot skill 自调试愿景可行，但第一篇论文应收紧为“frozen VLA harness 中共享 implementation 的 verifier-gated repair”，不要定位成替代 VLA、开放式 lifelong evolution 或通用 AGI 机器人。

## 为什么可行

第一，机器人系统本来就是模块化软件。感知接口、坐标变换、规划、控制、状态机、skill-local completion monitor、fallback 和安全约束，都有很多可由代码表达的部分；外部 benchmark success predicate 则必须独立保护。

第二，很多机器人失败并不需要重新训练大模型。例如：

- 坐标系转换错。
- 深度图无效值没过滤。
- planner error code 没处理。
- 抓取点候选策略太脆。
- precondition 太宽。
- postcondition 太弱。
- fallback 缺失。

这些问题很适合 coding agent 修复。

第三，已有工作已经证明了关键组件：

- LLM 可以高层调度 skill：SayCan、Inner Monologue。
- LLM 可以生成机器人代码：Code as Policies、VoxPoser。
- skill library 可以通过经验增长：Voyager、LRLL。
- 代码可以靠 evaluator 迭代进化：Eureka、AlphaEvolve。
- 机器人 LLM 计划/程序需要验证：NRTrans、SELP、SafePlan。

所以本项目不是空中楼阁，而是把这些趋势组织成一个更工程化的闭环。

## 新来源如何改变判断

[[Harness VLA]] 为“VLA + 解析控制 + agentic planner”的混合系统提供了比过去更直接的证据：冻结 VLA 只负责局部接触丰富阶段，外部 harness 通过语义 re-grounding、staging、memory 和 retry 就能改善 LIBERO-Pro、RoboCasa365 与 RoboTwin C2R 的仿真表现。

这同时缩小了本项目可主张的新意。planner、memory 和 fixed primitive composition 本身已经不是空白；在 ASPIRE 之后，failure trace 与 program repair 也不是空白。本项目必须进一步落到共享既有 implementation、最小充分干预路由、`Δmemory × Δcode` 因果对照，以及 hidden cross-task regression/safety 验收。

[[Harness Engineering for Self-Improvement - 综述解读|Harness Engineering for Self-Improvement]] 则支持更长期的 [[机器人Harness工程]] 叙事，但其主要证据来自 coding、QA、science 和 game benchmark。把 harness 自动修改迁移到真实机器人仍是**研究假设**，不是已有事实。

[[ASPIRE]] 进一步覆盖了多模态 trace 驱动的 robot program repair、validation、skill guidance library 和 evolutionary search；[[VASO]] 已覆盖 formal verifier-guided semantic skill contract evolution。因此，“trace → repair → skill 积累”与“verification-guided self-evolving skill”都不能再被当作本项目独有。

[[HELM]] 说明 memory、state verifier 和 rollback/replanning 可以在不改代码时恢复大量 VLA failure；[[InSight]] 则说明真正缺失的低层 primitive 应通过数据 flywheel 与 policy update 获取。这两条路线共同要求我们先按最小充分干预区分 plan/memory、code 与 policy failure。

## 最有价值的部分

目前最值得单独验证的不是“LLM 写出一个很聪明的 skill”，也不是宽泛闭环，而是：

1. 用最小充分干预和 oracle 反事实预注册 failure type。
2. 在同一 frozen harness 上把 plan/memory 与 code edit 做成因子对照。
3. 修复跨任务共享的既有 implementation，而不是为每个 task 临时生成程序。
4. 用 final-blind、mutation-strengthened regression 和 safety gate 判断 patch 是否语义正确。
5. 把 evaluator、预算、外部 success predicate 和部署权留在 repair loop 之外。

长期 skill library 复利仍重要，但应等单次 repair 成立后再作为后续 sequential/lifelong 假设。

## 不能过度承诺的部分

不要承诺：

- 纯靠 coding agent 解决所有低层控制。
- 不需要机器人数据。
- 不需要 learned policy。
- 可以自动安全地在真实机器人上无限试错。
- 短期替代 VLA。

真实情况是：很多操作能力依然需要 imitation learning、RL、diffusion policy、VLA 或专门控制器。coding agent 更适合作为 skill 周围的工程维护者、调试员和系统集成者。

## 最适合 coding agent 修的失败

适合：

- 几何计算错误。
- API 调用和参数错误。
- 阈值和置信度处理。
- fallback 策略。
- precondition/postcondition。
- skill 内部的 local postcondition/monitor。
- 异常处理。
- 测试缺失。

不适合：

- 需要高频触觉闭环的灵巧操作。
- 布料、液体、柔性物体的复杂动力学。
- 视觉模型完全没有识别能力。
- 硬件本身不够稳定。
- 没有可测 evaluator 的开放式目标。

外部 success predicate、benchmark adapter、timeout/truncation 聚合和评分逻辑即使有 bug，也属于 trusted-kernel/out-of-scope；agent 应上报和 abstain，不能把它们当作可编辑 success detector。

## 叙事建议

弱叙事：

> 我们用 coding agent 替代 VLA，实现机器人 AGI。

强叙事：

> 在冻结 RPent/Harness VLA 的 planner、VLA、初始 memory、evaluator 和预算后，我们检验受验证的共享 skill implementation repair 是否能在预注册的 code-repairable failures 上超过 plan/memory-only recovery，并在 final-blind 场景保持无回归、安全增量。

后者更科学，也更容易做实验。

## 关键研究假设

第一篇 confirmatory experiment 只设一个 primary：在预注册 code-repairable families 上，gated code repair 相比 compute-matched plan/memory-only Harness 提高 final-blind success/normalized recovery，同时满足 regression 非劣与零 severe safety violation。

secondary hypotheses 检验三件事：

1. `allow_code_edit × failure_type` 的选择性，并在 plan/policy/trusted-kernel cases 正确 abstain；
2. patch 跨 seed、对象变化和调用同一 skill 的其他任务泛化；
3. verifier 与 structured trace（H5）是否分别降低 false acceptance、回归和 repair cost。

“代码修复是否比模型微调更样本高效”和“skill library 是否在 lifelong setting 复利”保留为后续研究，不与第一篇主假设混合。完整编号、margin 与推翻条件见 [[问题定义与实验假设]]。

正式检验时不能把四类失败混在一个总体成功率里。应按“最小充分干预”区分 plan/memory-repairable、code-repairable、policy-limited 与 trusted-kernel/out-of-scope，并把代码修复的主假设限定在预注册的 code-repairable failure families。操作化定义、对照组和推翻条件见 [[问题定义与实验假设]]。
