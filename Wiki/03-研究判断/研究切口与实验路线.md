# 研究切口与实验路线

核心判断：第一篇论文/项目应该聚焦“失败驱动的 robot skill 程序修复”，而不是试图一次性做通用家庭机器人。

## 推荐题目

英文：

> Self-Debugging Robot Skills: Execution-Feedback Program Repair for Embodied Manipulation

中文：

> 基于执行反馈的机器人技能自调试与程序修复

## 研究问题

给定：

- 一个有缺陷的 robot skill。
- 一次或多次失败执行 trace。
- skill registry、API 文档和测试环境。

问题是：

> LLM coding agent 能否提出一个安全 patch，使该 skill 在相似和变化场景中成功率提高，同时不破坏旧任务？

## 与 Harness VLA 的区别

[[Harness VLA]] 已经证明，冻结 VLA 配合固定 primitive、task-specific trace memory、planner re-grounding 和局部 retry，可以在扰动 benchmark 上大幅提升。它是本项目现在必须正面对比的直接近邻。

因此，第一篇论文不能只证明“agent + memory + primitives 比端到端 VLA 更好”。它必须进一步证明：

> 在控制 planner、memory、retry budget 和 VLA backend 后，允许 agent 修改并验证 skill/harness 的受限实现，能否修复 fixed harness 仍然失败的 held-out cases，并保持旧任务无回归？

## 最小可行系统

第一阶段只做 3 个模块：

1. Skill registry：记录 skill 的输入、输出、precondition、postcondition、安全约束、测试。
2. Trace collector：记录失败时的关键状态和多模态证据。
3. Repair loop：coding agent 生成 patch，verifier 运行测试，失败则回传结果。

不要一开始做完整自然语言家庭管家。任务大脑可以先很简单，甚至由脚本固定调用 skill。

## 实验任务

建议从桌面 manipulation 开始：

- 抓杯子。
- 抓带柄杯。
- 把杯子放进盒子/水槽区域。
- 打开抽屉。
- 擦拭桌面指定区域。

每个任务设计 2 到 4 种故意缺陷：

- 感知缺陷：深度空洞、遮挡、错误 mask。
- 几何缺陷：坐标系变换错误、抓取点偏移。
- 规划缺陷：IK 失败没有 fallback。
- 执行缺陷：力阈值太低或太高。
- 验证缺陷：success detector 错判。

## 实验流程

```text
1. 运行初始 skill，收集失败 trace。
2. coding agent 做 failure attribution。
3. agent 生成 patch proposal 和新增测试。
4. verifier 运行 unit/sim/regression/safety tests。
5. 如果失败，把测试输出回传 agent。
6. 如果通过，部署到下一批 held-out 场景。
7. 记录成功率、修复轮数、regression 和安全违规。
```

## Baseline

至少需要五个 baseline：

1. No repair：静态 skill library。
2. Retry only：失败后只重试或换随机参数。
3. Harness VLA-style fixed harness：允许 planner re-ground、重新 staging、使用 task/global memory，但禁止修改 primitive 或 skill 实现。
4. LLM plan repair：只让 LLM 改高层调用顺序，不改 skill 实现。
5. One-shot code generation：类似 Code as Policies，每次生成代码但不维护版本和回归测试。

可选 baseline：

- OpenVLA/Octo/pi0 作为 learned policy。
- 人类工程师修复作为上界。

## 指标

核心指标：

- 初始成功率 vs 修复后成功率。
- 每个缺陷平均修复轮数。
- held-out 场景成功率。
- regression rate。
- 安全违规次数。
- agent patch 被拒绝次数。
- 人类介入时间。

辅助指标：

- failure attribution 准确率。
- 新增测试是否覆盖真实失败。
- patch 大小和复杂度。
- 是否产生不可解释或绕过安全门的代码。
- harness-updating 成功率：proposal 是否正确修改目标组件并通过局部 evaluator。
- harness-benefit：完整 planner 是否在 held-out task 中实际调用并受益于新 skill/tool。

## 里程碑

### Milestone 1：纯仿真 proof-of-concept

在 robosuite、LIBERO 或 RoboCasa 中实现 3 个 skill 和 6 到 10 个故意缺陷。证明 agent 能修复一部分可归因错误。

### Milestone 2：回归测试和 skill library

为每个 skill 建 regression suite。测试修复 A 是否破坏 B，并记录 skill 版本。

### Milestone 3：真实机械臂小样本验证

选择 Franka、UR5、xArm、ALOHA 或 LeRobot 风格平台，在低速低力设置下验证 2 到 3 个 skill。

### Milestone 4：论文级 benchmark

发布一个“有缺陷 skill library + failure trace + repair evaluator”的 benchmark，让其他方法也能比较。

## 最小论文贡献

2. Execution trace schema。
3. Failure attribution + code repair agent。
4. Robot CI/CD verifier。
5. 缺陷 skill benchmark。
