## 1. VLA 与机器人基础模型

| 来源 | 关键信息 | 对本项目的意义 |
| --- | --- | --- |
| [RT-1: Robotics Transformer for Real-World Control at Scale](https://arxiv.org/abs/2212.06817) | 大规模真实机器人数据训练 transformer 控制策略。 | 说明机器人 foundation policy 的数据规模路线。 |
| [[rt-2-2307.15818.pdf|RT-2: Vision-Language-Action Models Transfer Web Knowledge to Robotic Control]] | 把 web-scale VLM 知识迁移到机器人动作输出。 | 是“端到端 VLA”叙事的重要起点之一。 |
| [Open X-Embodiment: Robotic Learning Datasets and RT-X Models](https://arxiv.org/abs/2310.08864) | 汇集多机构、多机器人、多任务数据，训练跨 embodiment policy。 | 说明 VLA 的可扩展性依赖大量标准化数据。 |
| [Octo: An Open-Source Generalist Robot Policy](https://arxiv.org/abs/2405.12213) | 基于 Open X-Embodiment 的开源通用机器人 policy。 | 可作为未来实验 baseline 或 skill 实现方式。 |
| [[openvla-2406.09246.pdf|OpenVLA: An Open-Source Vision-Language-Action Model]] | 7B 开源 VLA，在多任务 manipulation 上表现强。 | 是需要正面对比的开源 VLA 路线。 |
| [pi0: A Vision-Language-Action Flow Model for General Robot Control](https://arxiv.org/abs/2410.24164) | 用 flow matching 生成连续机器人动作。 | 代表 VLA 从离散 action token 走向连续控制的路线。 |
| [pi0.5: a Vision-Language-Action Model with Open-World Generalization](https://arxiv.org/abs/2504.16054) | 面向开放家庭环境泛化，结合高层语义预测和低层动作。 | 和“清理厨房/房间”的目标场景直接相关。 |
| [GR00T N1: An Open Foundation Model for Generalist Humanoid Robots](https://arxiv.org/abs/2503.14734) | NVIDIA 的人形机器人 VLA，采用类似双系统架构。 | 说明“高层理解 + 快速动作模型”已是产业/研究热点。 |
| [Gemini Robotics: Bringing AI into the Physical World](https://arxiv.org/abs/2503.20020) | Google DeepMind 的 Gemini Robotics 与 Robotics-ER。 | 证明大模型公司正把 VLM/VLA 推向真实机器人。 |
| [Gemini Robotics 1.5](https://arxiv.org/abs/2510.03342) | 强调 embodied reasoning、thinking 与 motion transfer。 | 最新 VLA 更重视可解释推理，但仍是模型参数路线。 |
| [Embodied-R1.5](https://arxiv.org/abs/2606.11324) | 2026 年提出的 embodied foundation model，包含规划、纠错、指向等能力。 | 代表“单模型内化 embodied 能力”的新近方向，需要持续跟踪。 |
| [[Harness VLA]] | 把冻结 VLA 封装为可重试 `VLA_ACT`，由 planner、memory 和解析 primitive 负责重绑定、staging 与长时序组合。 | 是本项目混合架构最直接的 baseline；同时表明只做 fixed-harness orchestration 已不足以构成 code self-evolution。 |
| [Diffusion Policy](https://arxiv.org/abs/2303.04137) | 用 diffusion 生成视觉运动策略。 | 可作为复杂低层 skill 的 learned policy 实现，而非系统竞争者。 |
| [Learning Fine-Grained Bimanual Manipulation with Low-Cost Hardware / ACT](https://arxiv.org/abs/2304.13705) | 用 action chunking transformer 学习精细双臂操作。 | 说明某些接触丰富动作更适合 learned policy，不适合纯代码规则。 |

## 2. LLM 规划、skill 调用与机器人代码生成

| 来源 | 关键信息 | 对本项目的意义 |
| --- | --- | --- |
| [[saycan-2204.01691.pdf|Do As I Can, Not As I Say / SayCan]] | LLM 负责高层语义推理，value function/affordance 约束可执行 skill。 | 和“任务大脑调度已有 skill”最接近。 |
| [Inner Monologue](https://arxiv.org/abs/2207.05608) | 让 LLM 利用成功检测、场景描述和人类反馈做闭环规划。 | 证明环境反馈能改善高层 embodied reasoning。 |
| [ProgPrompt](https://arxiv.org/abs/2209.11302) | 用程序化 prompt 生成可执行机器人任务计划。 | 支持把动作、对象、约束写成结构化上下文。 |
| [[code-as-policies-2209.07753.pdf|Code as Policies]] | 让代码模型生成 robot policy code，组合 perception output 与控制 API。 | 是“LLM 写机器人 skill 代码”的核心相关工作。 |
| [[voxposer-2307.05973.pdf|VoxPoser]] | LLM/VLM 组合 3D value maps，再交给 model-based planner 生成轨迹。 | 与“像素/深度/三维位置 + 传统控制”的想法很贴近。 |
| [Lifelong Robot Library Learning](https://arxiv.org/abs/2406.18746) | LLM 持续增长可组合 robot skill library。 | 和“skill library 会随经验增长”高度相关。 |
| [Towards Reliable Code-as-Policies](https://arxiv.org/abs/2510.21302) | 在 Code-as-Policies 中加入符号验证和互动验证。 | 支持“生成代码必须被验证，而不是直接执行”。 |

## 3. 代码自进化、反馈循环与 evaluator

| 来源 | 关键信息 | 对本项目的意义 |
| --- | --- | --- |
| [[voyager-2305.16291.pdf|Voyager]] | Minecraft 中的 LLM lifelong agent，维护可执行代码 skill library，并用反馈改进。 | 是本项目最重要的思想近邻：技能以代码积累，而非参数微调。 |
| [Eureka](https://arxiv.org/abs/2310.12931) | LLM 写 reward code，通过 RL evaluator 优化机器人技能。 | 说明 coding agent 在机器人学习中可以作为“奖励/评估设计者”。 |
| [[alphaevolve-2506.13131.pdf|AlphaEvolve]] | LLM 直接修改算法代码，靠 evaluator 做进化式优化。 | 为“机器人 skill code + evaluator + 版本迭代”提供强范式参考。 |
| [Teaching Large Language Models to Self-Debug](https://arxiv.org/abs/2304.05128) | 研究 LLM 如何根据执行反馈调试自身生成的代码。 | 为 coding agent 修复 skill 代码提供软件工程侧依据。 |
| [InspectCoder](https://arxiv.org/abs/2510.18327) | 让 LLM 通过交互式 debugger 做动态分析和 self repair。 | 提醒机器人失败 trace 也应支持主动定位，而非只给最终报错。 |
| [[Harness Engineering for Self-Improvement - 综述解读|Harness Engineering for Self-Improvement]] | Lilian Weng 对 context、workflow、self-harness、evolutionary search 和 joint optimization 的 2026 年综述。 | 提供 [[机器人Harness工程]] 的术语与实验纪律：component observability、受限编辑面、只读 verifier 和 held-out 回归。 |

## 4. 安全、形式化约束与机器人 DSL

| 来源 | 关键信息 | 对本项目的意义 |
| --- | --- | --- |
| [[nrtrans-2508.19074.pdf|NRTrans: An LLM-powered Natural-to-Robotic Language Translation Framework with Correctness Guarantees]] | 提出 Robot Skill Language、compiler、debugger 来验证 LLM 生成的机器人控制程序。 | 直接支持“受约束 DSL + 编译器 + 调试反馈”的安全层。 |
| [SELP](https://arxiv.org/abs/2409.19471) | 用 LTL、constrained decoding 和 fine-tuning 生成安全高效任务计划。 | 可用于高层任务计划的形式化约束。 |
| [SafePlan](https://arxiv.org/abs/2503.06892) | 结合形式逻辑和 CoT reasoner 检查机器人任务 prompt 与计划安全。 | 支持部署前的 precondition/postcondition sanity check。 |
| [LTLCodeGen](https://arxiv.org/abs/2503.07902) | 将自然语言导航任务转成语法正确的 LTL，再规划路径。 | 说明“语言 -> 形式规格 -> planner”比端到端计划更稳。 |
| [Safe LLM-Controlled Robots with Formal Guarantees via Reachability Analysis](https://arxiv.org/abs/2503.03911) | 用 data-driven reachability analysis 给 LLM 控制机器人提供安全保证。 | 可为低层执行安全门提供形式化参考。 |
| [SAFER: Safety Aware Task Planning via Large Language Models in Robotics](https://arxiv.org/abs/2503.15707) | 多 LLM safety agent + Control Barrier Functions。 | 支持在任务规划和执行之间加入独立安全代理。 |
| [Forgetful Large Language Models: Lessons Learned from Using LLMs in Robot Programming](https://arxiv.org/abs/2310.06646) | 总结 LLM 机器人编程常见执行错误。 | 提醒 skill schema 和上下文管理必须防止 LLM 遗忘约束。 |

## 5. Benchmark、仿真与实验平台

| 来源 | 关键信息 | 对本项目的意义 |
| --- | --- | --- |
| [CALVIN](https://arxiv.org/abs/2112.03227) | 长时序语言条件机器人操作 benchmark。 | 适合测高层 task decomposition 和 skill composition。 |
| [[libero-2306.03310.pdf|LIBERO]] | lifelong robot learning benchmark，包含 130 个任务。 | 适合测试“修复一个 skill 后是否破坏旧任务”。 |
| [[robocasa-2406.02523.pdf|RoboCasa]] | 厨房环境大规模日常任务仿真框架。 | 与“清理厨房”设想最贴近。 |
| [RoboCasa365](https://arxiv.org/abs/2603.04356) | 365 个日常任务、2500 个厨房环境的大规模 benchmark。 | 是 2026 年更适合测试泛化和 lifelong 的平台。 |
| [BEHAVIOR-1K](https://arxiv.org/abs/2403.09227) | 1000 个日常活动，包含丰富物理和语义属性。 | 适合检验长时序、多对象、家庭任务复杂性。 |
| [RoboLab](https://arxiv.org/abs/2604.09860) | 用高保真仿真分析 task-generalist policies 的鲁棒性。 | 可用于构造系统化扰动测试和 regression suite。 |
| [robosuite](https://arxiv.org/abs/2009.12293) | MuJoCo 上的模块化机器人学习仿真框架。 | 适合搭建较轻量的 proof-of-concept。 |
